# IFE_Cluster_fast.py — 클러스터 포트폴리오 + 변동성 관리 레이어

`Cluster/IFE_Cluster.py`를 기반으로 한 개선판입니다. **기존 네 전략(Cluster v2, Cluster v1, Naive GMVP-LW, EW Market)의 결과는 원본과 같습니다.** 그 위에 벤치마크와 무위험수익률을 고치고, Moreira & Muir (2017)의 변동성 관리 레이어를 추가했습니다.

## 실행 방법

```
Cluster/IFE_Cluster_fast.py        ← 이 스크립트
data/market_rv_monthly.csv         ← 시장 실현분산 (없으면 Ken French에서 자동 다운로드)
data/tbill3m_monthly.csv           ← 3개월 T-bill (없으면 FRED에서 자동 다운로드)
data/sp500_monthly.csv             ← S&P500 월별 수익률 (없으면 yfinance로 자동 다운로드)
IFE_term_stock_data.csv            ← 이 폴더의 Cluster/, 이 폴더, 레포 루트, 레포 루트의 Cluster/ 중 한 곳
```

팀 레포에 이 폴더째 올린 경우, 원본 데이터를 원래 위치(레포 루트의 `Cluster/`)에 두면 그대로 찾습니다. CRSP 데이터는 `.gitignore`로 업로드에서 제외했으니 각자 받아서 넣으세요.

```
cd Cluster
python -u IFE_Cluster_fast.py
```

- 필요 패키지: `numpy`, `pandas`, `matplotlib`, `yfinance` (+ 선택: `pandas_datareader`)
- 소요 시간: 첫 실행 약 1시간 30분 (원본은 혼자 돌려도 3시간 이상, 다른 작업과 같이 돌면 10시간 이상)
- **중간에 꺼도 됩니다.** 매달 `Cluster/_checkpoint_mm.pkl`에 진행 상황을 저장합니다. 다시 실행하면 이어서 돌고, 끊어서 돌려도 한 번에 돌린 결과와 같습니다.
- **체크포인트는 완료 후에도 남아 캐시로 쓰입니다.** 무위험수익률(`RF_SOURCE`), 변동성 레이어 설정, 위기 구간(`CRISIS_WINDOWS`)만 바꿔 다시 돌리면 백테스트 루프를 건너뛰고 몇 초 만에 끝납니다. 클러스터링 파라미터를 바꾸면 자동으로 처음부터 다시 계산합니다. 강제로 다시 계산하려면 `_checkpoint_mm.pkl`을 지우세요.
- 출력 파일은 `_mm` 접미사가 붙어 원본 결과를 덮어쓰지 않습니다.

## 추가한 것: 변동성 관리 레이어 (Moreira & Muir, 2017, *Journal of Finance*)

```
x_t      = r_t − rf_t                         기초 포트폴리오의 월 초과수익률
RV_{t-1} = Σ_{d ∈ t-1} (Mkt-RF_d)²            직전 달 일간 시장 초과수익률의 제곱합
w_t      = c / RV_{t-1}                       다음 달 익스포저
관리 포트폴리오 수익률 = rf_t + w_t · x_t        (남는 돈은 rf로 운용, 부족한 돈은 rf로 차입)
```

세 가지 버전을 네 기초 전략에 각각 적용했습니다 (TV12m은 v2에만).

| 이름 | 설명 |
|---|---|
| **VM(M&M)** | 논문 원안. c는 관리 전후 전체기간 변동성이 같도록 설정, 레버리지 제한 없음. c가 전체 기간 정보를 쓰지만 Sharpe와 알파 t값은 c와 무관 |
| **VM(실시간,≤1.5x)** | 실제로 운용 가능한 버전. c를 매달 **과거 자료만으로** 추정 (최소 24개월, 그 전엔 w=1). 레버리지 0~1.5배. 1.5배는 M&M (2017) 본문(거래비용·레버리지 제약 절)에서 "표준 증거금 규제에 해당하는 50% 레버리지"로 제시한 제약을 따름 (참고: GitHub `IFE_Shrinkage.py`의 `LEV_CAP`도 1.5) |
| **TV12m(수정)** | 비교용. `Cluster_Portfolio_V2_60m.py`와 `IFE_Shrinkage.py`에 있던 방식 — 전략 자신의 과거 12개월 월간 수익률로 목표 변동성 10% 조정, 0~2배. 단, 원본은 **스케일 적용 후** 수익률로 다음 달 변동성을 추정해 자기 레버리지 결정이 다시 입력으로 들어가는 되먹임이 있었고, 여기서는 **스케일 적용 전** 수익률로 추정하도록 수정 |

**원본 오버레이와의 차이:** 12개월 월간 수익률(관측치 12개)은 변동성 급등에 늦게 반응합니다. M&M 방식은 직전 1개월 일간 수익률(관측치 약 21개)을 써서 빠르게 반응하고, 외부 시장 데이터라 되먹임이 원천적으로 없습니다.

**평가:** 관리 초과수익률을 비관리 초과수익률에 회귀한 알파 (M&M의 핵심 검정). `x^σ_t = α + β x_t + ε_t`, α > 0이면 변동성 관리가 가치를 더한 것. 표준오차는 White 이분산-강건.

### MDD 개선이 우연이 아닌가 (`cluster_vm_drawdown_mm.csv`, `cluster_vm_drawdown_mm.png`)

MDD는 가장 나빴던 한 번의 사건만 보는 지표라서, 세 가지로 확인했습니다.

1. **대조군:** 원본을 변동성 관리 버전과 같은 변동성이 되도록 **고정 비율로만** 줄인 포트폴리오 (Cluster v2는 0.81배). 이걸 이겨야 "덜 투자해서"가 아니라 "타이밍" 덕분이라고 할 수 있습니다.
2. **한 사건에 덜 좌우되는 지표:** 평균 낙폭, CDaR95(가장 나쁜 5% 낙폭의 평균), 낙폭 10% 이상인 달 비율, 기간별 MDD
3. **12개월 블록 부트스트랩 2,000회:** (원본, 변동성 관리) 월 수익률 쌍을 12개월 블록 단위로 섞어 역사를 재구성. 각 달의 실제 레버리지는 고정한 채 경로만 바꾸는 검정입니다.

결론: **메인 전략인 Cluster v2와 v1에서는 MDD 개선이 견고합니다.** 대조군을 이기고, 큰 하락이 있었던 두 기간(2003~2009, 2015~2020) 모두에서 개선됐고, 부트스트랩의 97% 이상에서 원본보다 나았으며 90% 구간이 0을 넘습니다. 반면 **Naive GMVP-LW와 EW Market에서는 확실하다고 하기 어렵습니다.** 부트스트랩 90% 구간이 0을 포함하고, 2015~2020년 MDD는 오히려 원본보다 나빴습니다 (EW -35.6% → -38.8%). 큰 하락이 없던 2010~2014년에는 v2도 대조군보다 못했습니다.

해석할 때 주의할 점:
- **레버리지 제한이 결과를 좌우합니다.** 논문 원안(무제한)은 저변동성 달에 최대 6배까지 레버리지를 올렸다가 조정장에서 크게 손실을 봐서 네 전략 모두 Sharpe가 **낮아졌습니다.** 대표 사례가 2018년 10월입니다. 직전 달 시장 변동성이 연 5.9%로 매우 낮아 원안은 레버리지를 3.98배로 올렸고, 그 달 기초 전략이 -5.6% 빠지면서 **한 달에 -23.0%** 손실이 났습니다. 원안의 MDD(2018-08 → 2018-12)는 2020년 말까지 회복하지 못했습니다. 같은 달 1.5배 제한 버전은 -8.5%에 그쳤습니다. 1.5배 제한 버전은 전 전략에서 Sharpe를 높였고, 약 3분의 1의 달이 상한에 걸렸습니다. 두 버전의 사양은 결과를 보기 전에 정했습니다 (1.5배는 M&M 논문의 강건성 검정 값).
- 성과 개선의 대부분은 **위기 때 익스포저를 줄인 데서** 나옵니다. 급락이 한 달 이상 이어진 금융위기·코로나에서는 손실을 절반 이하로 줄였지만, 대신 **직후 반등을 대부분 놓쳤습니다** (코로나 반등 +25.9% → +1.5%). 변동성이 높게 유지되는 동안 익스포저가 계속 낮았기 때문입니다.
- 짧고 갑작스러운 하락(중국 쇼크, 2018년 4분기)은 막지 못했습니다. 직전 달 변동성이 낮으면 익스포저가 높은 상태로 첫 하락을 그대로 맞고, 그다음 달에야 줄이기 때문입니다. 예를 들어 2015년 8월에는 직전 달 변동성이 11.6%라 1.04배로 -4.6%를 맞았고, 9월에 0.22배로 줄였다가 10월 반등(+5.9%)을 0.31배로만 받았습니다. 그래서 중국 쇼크 구간은 원본(-3.1%)보다 오히려 나빴습니다(-5.9%). 직전 달 정보로 움직이는 방식의 구조적 한계입니다.
- 기존 12개월 월간 방식(TV12m)은 알파가 사실상 0입니다 (t=0.09). 일간 RV를 쓰는 이유를 뒷받침합니다.
- 실시간 버전은 레버리지를 매달 평균 약 0.32 바꿉니다. 편도 10bp를 가정하면 연 약 0.4%p 비용이라 알파(3.7%)를 없앨 수준은 아니지만, 보고서에는 명시해야 합니다.

## 한계 (보고서에 명시 권장)

1. **RV는 시장 전체 변동성입니다.** CRSP 월간 패널에 일간 수익률이 없어서, 포트폴리오 자체가 아닌 시장(Ken French Mkt-RF)의 실현분산을 공통 대리변수로 썼습니다. 클러스터 포트폴리오의 변동성이 시장과 다르게 움직이는 구간에서는 타이밍이 부정확할 수 있습니다.
2. **거래비용 미반영.** 변동성 관리 레이어는 레버리지를 매달 크게 바꿉니다 (VM(M&M)은 최대 6배 수준). 회전율 비용을 반영하면 성과가 낮아집니다.
3. **차입 비용 = rf 가정.** 1배를 넘는 레버리지에 대해 실제보다 싼 비용을 가정합니다.
4. **레버리지 상한의 영향이 원 논문보다 큽니다.** M&M (2017)은 1배·1.5배 상한을 둬도 Sharpe가 거의 변하지 않는다고 보고하지만, 여기서는 상한 유무가 결과를 갈랐습니다 (Cluster v2 Sharpe: 무제한 0.622, 1.5배 상한 0.945). 원 논문은 팩터 자신의 변동성으로 그 팩터를 조절하는 반면, 여기서는 시장 변동성으로 클러스터 포트폴리오를 조절하기 때문으로 보입니다. 시장이 조용해 레버리지가 4~6배까지 올라간 달에 포트폴리오가 빠지면 손실이 커집니다 (예: 2018년 10월).
5. **VM(M&M)의 c는 사후적입니다.** Sharpe와 알파 t값에는 영향이 없지만, 누적수익·MDD 수준은 전체 기간 정보를 쓴 결과입니다. 실시간 버전을 함께 보고하는 이유입니다.
6. `DATA_CLEANING.md`에는 최소 관측 기간이 "60개월 이상"으로 적혀 있지만 코드(원본 포함)는 `MIN_HISTORY = 36`입니다. 결과 재현성을 위해 코드 값을 유지했습니다.
